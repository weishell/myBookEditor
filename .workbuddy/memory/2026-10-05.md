# 2026-10-05 工作日志

## 空段落「＋」直接铺开块/插件插入面板

需求：DocBar 悬停在**空段落**（图标为「+」）时，不要先弹整个块操作菜单再点「在下方插入」，
而是直接把块类型选择面板（BlockTypePicker，含流程图 DRAWIO / 画板 DRAWBOARD 等）铺开，
选中即在空行**原地插入**（替换该空行，不留空行）。

改动文件：`src/plugins/context-menu/ContextMenu.tsx`（仅此一个）

1. 新增 `isTargetEmptyParagraph`：`type===PARAGRAPH && !attrs.lilist && children.length===1 && children[0].text===''`。
   - 必须排除挂 lilist 的空列表项（列表项 DocBar 图标是列表图标，不是「+」）。
   - 判定与 `ElementWrapper` 的 `data-empty` / `Paragraph.tsx` 的 isEmpty 语义对齐。
2. `handleInsertBlock` 锚点逻辑：空段落时 `anchorPath = getTargetPath()`（悬停的那个空行），
   不再被「光标所在的另一空行」抢锚点；其它块沿用原逻辑。
   - 之后 `isAnchorEmpty` → `removeNodes` 原地替换，逻辑复用不变。
3. 渲染分支：`isTargetEmptyParagraph` 时提前 return，menu 内容只渲染 `<BlockTypePicker onSelect={handleInsertBlock} />`
   （`renderChartFlow`/`renderEmbedFlow` 仍保留）。非空块走原菜单（含「在下方插入」Popover）。

关键背景（本项目约定）：

- 编辑器基于 **Slate**；块都有 `id/type/attrs/children`。
- DocBar（左侧悬浮图标）由 `DocBar.tsx` 渲染，`onMouseEnter` 调 `openMenu(id,x,y)` 打开
  `ContextMenu`（menu-context 的 `MenuContext`）。**是 hover 打开，不是 click。**
- 「空」判定：`ElementWrapper` 打 `data-empty` 属性 → `DocBarContext` 读取为 `activeElement.isEmpty`。
- `createBlockNode`（block-picker/block-nodes.ts）负责按类型构造合法节点。
