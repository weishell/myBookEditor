## 空段落「＋」直接铺开块/插件插入面板

需求：DocBar 悬停在**空段落**（图标为「+」）时，不要先弹整个块操作菜单再点「在下方插入」，
而是直接把块类型选择面板（BlockTypePicker，含流程图 DRAWIO / 画板 DRAWBOARD 等）铺开，
选中即在空行**原地插入**（替换该空行，不留空行）。

改动文件：`src/plugins/context-menu/ContextMenu.tsx`（仅此一个）

1. 新增 `isTargetEmptyParagraph`：`type===PARAGRAPH && !attrs.lilist && children.length===1 && children[0].text===''`。

   - 判定与 `ElementWrapper` 的 `data-empty` / `Paragraph.tsx` 的 isEmpty 语义对齐。

   不再被「光标所在的另一空行」抢锚点；其它块沿用原逻辑。
   - 之后 `isAnchorEmpty` → `removeNodes` 原地替换，逻辑复用不变。

## 让「公式 / @提及」也能被改颜色（文字色 / 背景色）

需求（用户原话）："公式和艾特如果被选中，然后调整颜色的话，应该根据背景色或者文字颜色允许变化"。

问题根因：`FORMULA`、`MENTION` 在 Slate 里是 **`isInline: true` + `isVoid: true`**（见 `withInlineFormula.ts` / `withMention.ts`），
且渲染时**不渲染 children**（`core/renderElement.tsx` 里 `<Formula/>`/`<Mention/>` 都不接 children）。
而颜色是 text mark —— Slate 的 `addMark` 默认不进入 void 节点内部，所以"选中公式改颜色"的 mark 根本落不到它们身上。

方案：**颜色写到元素自己的 `attrs`（`color` / `highlight`），不放 text mark。**

1. 新增 `src/utils/inline-mark-style.ts`：`getInlineMarkStyle(element, isDarkMode)` 从 `element.attrs.color/highlight`
   取色，转成内联样式；暗黑模式下"接近黑"的文字色柔和化为 `SOFT_WHITE`（复用 `@/core/renderLeaf` 导出的
   `DARK_TEXT_PATTERN`/`SOFT_WHITE`，与正文叶子保持一致）。
2. `src/plugins/formula/Formula.tsx`、`src/plugins/mention/Mention.tsx`：读该样式套到根 span 的 `style`
   （inline style 会覆盖 `.formula` 的 hover 蓝底 / `.mention` 的 `var(--theme-primary)`）。
   - 注意 `Mention.module.less` 的 `.selected { background: … !important }` —— 选中态仍是蓝色高亮，符合预期。
3. `src/plugins/marks.ts` 的 `setColor` / `setBackgroundColor`：在原有 `addMark`/`removeMark` 之外，
   新增 `setInlineElementColor()` —— 用 `Editor.nodes(editor, { at: selection, voids: true, match: 类型是 FORMULA/MENTION })`
   找出选区内的自绘行内元素，逐个 `Transforms.setNodes(editor, { attrs: 合并后的 }, { at: path })`。
   **必须带 `voids: true`**（否则匹配不到 void 节点）—— 这正是仓库既有约定
   （`calendar-node.ts` / `withChart.ts` / `embed-node.ts` 的 "写 void 元素 attrs" 都是这个写法）。
   → 这样 FloatBar 的颜色按钮和右键菜单的「颜色」两处入口**都自动生效**。

验证：`tsc -b` 零新增报错；`vite build` modules transformed 成功。

未做（用户明确说可选）：公式/提及**以外的**自绘元素（画板、图表、倒计时…）没接颜色；这是块级元素，语义也不同，未纳入。
