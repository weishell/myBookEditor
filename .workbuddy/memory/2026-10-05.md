## 让「公式 / @提及」也能被改颜色（文字色 / 背景色）

需求（用户原话）："公式和艾特如果被选中，然后调整颜色的话，应该根据背景色或者文字颜色允许变化"。

问题根因：`FORMULA`、`MENTION` 在 Slate 里是 **`isInline: true` + `isVoid: true`**（见 `withInlineFormula.ts` / `withMention.ts`），
且渲染时**不渲染 children**（`core/renderElement.tsx` 里 `<Formula/>`/`<Mention/>` 都不接 children）。
而颜色是 text mark —— Slate 的 `addMark` 默认不进入 void 节点内部，所以"选中公式改颜色"的 mark 根本落不到它们身上。

方案：**颜色写到元素自己的 `attrs`（`color` / `highlight`），不放 text mark。**

1. 新增 `src/utils/inline-mark-style.ts`：`getInlineMarkStyle(element, isDarkMode)` 从 `element.attrs.color/highlight`
   取色，转成内联样式；暗黑模式下"接近黑"的文字色柔和化为 `SOFT_WHITE`（复用 `@/core/renderLeaf` 导出的
   `DARK_TEXT_PATTERN`/`SOFT_WHITE`，与正文叶子保持一致）。
2. `src/plugins/formula/Formula.tsx`、`src/plugins/mention/Mention.tsx`：读该样式套到根 span 的 `style`
   （inline style 会覆盖 `.formula` 的 hover 蓝底 / `.mention` 的 `var(--theme-primary)`）。
   - 注意 `Mention.module.less` 的 `.selected { background: … !important }` —— 选中态仍是蓝色高亮，符合预期。
3. `src/plugins/marks.ts` 的 `setColor` / `setBackgroundColor`：在原有 `addMark`/`removeMark` 之外，
   新增 `setInlineElementColor()` —— 用 `Editor.nodes(editor, { at: selection, voids: true, match: 类型是 FORMULA/MENTION })`
   找出选区内的自绘行内元素，逐个 `Transforms.setNodes(editor, { attrs: 合并后的 }, { at: path })`。
   **必须带 `voids: true`**（否则匹配不到 void 节点）—— 这正是仓库既有约定
   （`calendar-node.ts` / `withChart.ts` / `embed-node.ts` 的 "写 void 元素 attrs" 都是这个写法）。
   → 这样 FloatBar 的颜色按钮和右键菜单的「颜色」两处入口**都自动生效**。

验证：`tsc -b` 零新增报错；`vite build` modules transformed 成功。

未做（用户明确说可选）：公式/提及**以外的**自绘元素（画板、图表、倒计时…）没接颜色；这是块级元素，语义也不同，未纳入。

## 修复 Netlify 构建失败：`tsc -b` 全绿（3 个文件 / 32 处报错）

Netlify 的 build command 是 `pnpm run build` = **`tsc -b && vite build`**，所以 `tsc -b` 有任何报错都会让部署失败。
（本地之前一直"看起来没事"，是因为我只在本地跑 `vite build` —— esbuild 不做类型检查，全被漏过了。）

排查手法：`node node_modules/typescript/bin/tsc -b 2>&1 | grep -oE "^src/[^(]+" | sort | uniq -c | sort -rn`
→ 按文件统计报错数。本次 3 个文件：withPasteConversion 27、inline-comment/mark 4、ContextMenu 1。

**① `src/editor-extensions/withPasteConversion.ts`（27 处，根因最典型）**
从 slate 导入了 `Element`，**把 DOM 全局 `Element` 遮蔽了**；而该文件通篇操作 DOM 节点树
（`.tagName` / `.childNodes` / `.querySelector` / `getAttribute` / `Node.TEXT_NODE`）。
slate 的 `Element` 没有这些成员 → 一片 TS2339/TS2345/TS2677/TS2352。
修法：`import { ... Element as SlateElement ... } from 'slate'`，只把 `Element.isElement(n)` 改成 `SlateElement.isElement(n)`，
其余 `Element` 自动回落为 DOM 的 → 27 处全消。

> 教训：**在这个项目里 import slate 时，`Element` / `Node` / `Text` 一律起别名**，别遮蔽 DOM 同名全局。

**② `src/plugins/inline-comment/mark.ts`（4 处）**
根因：`CustomTypes`（`src/core/types.ts` 的 `CustomText`）**漏了评论用的 `comments` mark**，
于是只能 `as Partial<Node>` 硬 cast —— 而 `Partial<Node>` 是联合类型（含 Editor），TS 匹配到了 Editor 分支 → TS2345/TS2352；
`Array.from(gen as any)` 又让元素类型退化成 `unknown` → 解构报 TS2488。
修法：

- `core/types.ts` 的 `CustomText` 加 `comments?: string[] | null;`（null 表示无评论）；
- mark.ts 去掉两处 `as Partial<Node>`，直接传 `{ comments: ... }`；
- `removeCommentId` 改成 `const entries = Array.from(Editor.nodes(...)) as Array<[Node, number[]]>`（保留 `Node` 的 import 用途）。

**③ `src/plugins/context-menu/ContextMenu.tsx:22`（1 处）**
`TextAlignValue` 定义在 `src/enums/block.ts`，`utils/alignment.ts` 只 type-import 未再导出。
修法：在 `alignment.ts` 加 `export type { TextAlignValue };`（对齐模块对外提供自己的类型，消费方不用改）。

结果：`tsc -b` **EXIT=0，0 报错**；`vite build` modules transformed 成功
（本地 `vite build` 最后仍会因沙箱拦截清 `dist/assets` 而失败，**只影响本地**，Netlify 正常）。

约定补充：以后交付前**必须**跑一次 `tsc -b`（或 `pnpm build`），不能只跑 `vite build`。

### 修复：多行选区时对齐/缩进面板整片变灰（"多选不能控制"）

**根因（已用最小脚本实证）**：`Editor.above()` 对**跨多块的非折叠选区**返回 `undefined`。
之前 FloatBar 用它取"选区所在块" → `selectionBlock = null` → `disabled = true` → 面板全灰。
（对照实验：`Editor.nodes({ at: 选区, mode: 'highest' })` 跨多块正常返回 3 个段落；
`Editor.above({ at: 同一个多块选区 })` → `undefined`；单块选区才正常。）

> 结论：**取"选区涉及的块"永远用 `Editor.nodes(..., mode:'highest')`，不要用 `Editor.above`。**

修法（让 UI 判定与真正执行改动的取块逻辑**同源**）：

- `utils/alignment.ts` 导出 `getSelectionAlignBlocks(editor)`（包装内部 `getAlignTargets`）。
- `utils/indent.ts` 导出 `getSelectionIndentBlocks(editor)`（包装内部 `getSelectedBlocks`）；
  **删掉上一轮加的 `setSelectionIndent`**（被下面的列表感知版取代）。
- FloatBar：`formatBlocks = getSelectionIndentBlocks(editor) ?? getSelectionAlignBlocks(editor)`
  （INDENTABLE ⊆ ALIGNABLE，取交集更稳）；`disabled = !formatBlocks?.length`；
  当前缩进取 `min`(用于"-"禁用判定) 与 `max`(用于"+"禁用判定)。
- 顺手删掉 FloatBar 里的 `setFormatTick` —— `useSlate()` 本来就会在文档变化时重渲染
  （slate-react 的 `Editable`/`useSlate` 订阅 selector context，`<Slate onChange>` 会触发通知），
  代码里"onChange 是 no-op 所以不重渲染"的注释是旧的/误导的。

### 有序列表缩进必须重排序号（用户明确要求）

- 新增 `src/plugins/lilist/lilist-commands.ts` 的 `indentSelection(editor, dir: 1|-1)`：
  选区顶层块 ±1 缩进；**列表项会连带其后"更深的同组子项"整支平移**（保持树形不被拆散），
  末尾统一 `sortLilist(editor, [listIds])` 重排序号。
  - 语义刻意**不加** Tab 键的「不超过前一块 +1 / 首块不可缩进」约束（那是 `increaseIndent` /
    `indentLilistSubtree` 的键盘语义，按钮上用了会经常 no-op）；与 `setBlockIndent` 一致（夹 [0, MAX_INDENT]）。
  - 放在 lilist 模块里是为了避免 `utils/indent` ↔ `plugins/lilist` 的循环依赖（后者已 import 前者的 MAX_INDENT）。
- `AlignIndentPanel` 新增可选 `indentMin` / `indentMax`：多块选区时"+"看 max、"−"看 min，禁用判定才正确。
- `ContextMenu.handleIndent` 也补了 `sortLilist`：块菜单里对列表项缩进同样要重排序号（两处行为一致）。

注：多行**块类型转换**（T ▾ → H1 等）本来就支持 —— `toggleBlock` 用 `Transforms.setNodes` 不带 `at`，
默认作用于当前选区，多块选区天然生效，无需改。

### 真凶（第二层）：`Editor.nodes` 的 match 漏了 `Element.isElement` 守卫

用户反馈"点击无效果"。面板已经不变灰（取块修好了），但点"增加缩进"仍无反应。

**根因（已用真实源码 + esbuild 打包在 Node 里复现并验证）**：
`indentSelection` 里的 match 我写成了 `(n) => Editor.isBlock(editor, n)`，
在 `mode: 'highest'` 下**编辑器根节点也会命中**（探针显示 yields `type=undefined, path=[]`），
于是 "highest" 不再向下遍历 → 一个块都拿不到 → `picked` 为空 → 直接 `return false`。
而 `getSelectionIndentBlocks` / `getAlignTargets` 的 match 都有 `Element.isElement(n) &&` 前置守卫，
所以它们正常 → 面板是亮的、但点击无效（假象：看起来能用）。

修法：`match: (n) => Element.isElement(n) && Editor.isBlock(editor, n)`。

> **铁律：凡是 `Editor.nodes` 的 match 用 `Editor.isBlock`，前面前置 `Element.isElement(n)`。**
> 否则 `mode: 'highest'` 会把编辑器根当成"最高块"。

**验证手法（很有用，值得复用）**：本地没有可用的浏览器/Chrome 时，把真实源码用 esbuild 打包成
Node 可跑脚本，直接对真函数做断言 —— 比猜快得多：

```
"<managed>/node.exe" node_modules/.pnpm/esbuild@0.25.12/node_modules/esbuild/bin/esbuild \
  _probe.ts --bundle --platform=node --format=esm --outfile=_probe.mjs \
  --alias:@=./src --loader:.less=empty --log-level=warning
"<managed>/node.exe" _probe.mjs
```

（要 import 子模块路径而不是 `@/plugins/lilist` 桶，避免把 .tsx/.less 都拉进来；
`--loader:.less=empty` 用来吞掉样式导入。用完记得删探针文件。）

修复后实测（多块选区）：

- `setBlockAlignment('center')` → true，3 个块都写入 `align=center` ✓
- `indentSelection(+1)` → true，缩进 `[0,1,0]`；**有序列表编号自动从 `[1,2,3]` 重排为 `[1,1,2]`** ✓
