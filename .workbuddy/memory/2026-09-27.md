## 实现 Notion 式「先选中、再删除」+ 跨表格选区吸附整表选中

### 1. Backspace/Delete 选中非文本组件（withDelete.ts）

- 新增 `isWholeSelectableNode`：void 块（NON_TEXT_TYPES 全表）或 TABLE 可整体选中删除。
- `tryRemoveSelectedBlock`：选区正「选中一个完整块」时直接删除整块——
  void 块两端都在块内即删（void 选区只会 collapsed 落在隐藏文本 [i,0,0]）；
  表格必须恰好覆盖整表（Editor.start/end），防止误删单元格内局部选中文字。
  删除后 `moveSelectionAfterRemoval` 把光标放到后一块块首/前一块块尾。
- `trySelectAdjacentBlock('backward'|'forward')`：光标在顶层块真正起点/终点
  （Editor.isStart/isEnd at [topIdx]，跨过列表/单元格层级）且紧邻块可整体选中
  → 第一次按键只选中（Transforms.select 整块范围），不删除。
- 分别插入 deleteBackward/deleteForward 最前面，并把 relinkAfterDelete 补到删除整块路径。

### 2. 跨表格选区吸附（新文件 editor-extensions/withBlockSelection.ts）

- apply 层拦截 set_selection：合并 newProperties 与当前 selection 成候选选区，
  展开且恰好一端在顶层 TABLE 内、一端在外 → 改写为 Editor.range(editor, [i]) 整表选区。
- 改写后两端都在表内 → 不会递归。接入 core/index.tsx 的 withXxx 链
  （withSlashCommand 内层、withLilist 外层），tsc/build 通过。

### 3. 整表选中视觉（Table.tsx + Table.module.less）

- `useSlateSelector`（不是 useSlateStatic，需要选区变化触发重渲染）计算 isWholeSelected：
  选区恰好 isStart×isEnd 覆盖整表 path。
- 命中时在 scrollContainer 渲染全表 cellRangeHighlight 覆盖矩形
  （rowDots[0]/末项、colDots[0]/末项正好是表格四边），并给 <table> 加 `.wholeSelected`。
- CSS：`.wholeSelected ::selection { background: transparent !important; color: inherit; }`
  隐藏单元格文字原生选区（!important 压过 index.css 主题色 ::selection / dark-mode 变体）。

### 行为链路

- 表格下方块首按 Backspace → 选中整表（高亮+隐藏内部文字选区）→ 再按 Backspace → 删整表。
- Delete 对称（块尾 + 下方组件）。
- void 块（图片等）：块首次按选中（useSelected 插件自带高亮），再按删除；方向键移入 void 后直接删。
- 从表格外拖选划入表格 → 选区吸附为整表，内部无文字选区；此时 Ctrl+C 复制整表。

## 第二轮返工（同日，用户实测反馈）

### 用户反馈与根因（agent-browser 运行时诊断确认）

1. **跨表选区丢失外部选区**：原实现把整个选区改写成整表范围 → 表格外文字的选区被丢。
   修复：只把「落在表格内的那一端」吸附到表格边缘（外部端点在表前→吸到表尾；在表后→吸到表头），
   外部端点原样保留。运行时验证：anchor [41,0] 保留 + focus 吸到 [42,3,3,0,0]@10（表尾）✓
2. **日历/文件/提示块不生效**：
   - 日历/倒计时：删除逻辑其实生效（选区正确变成整块），但组件没有 useSelected 选中视觉 → 看起来没生效。
   - 提示块 hint-block：根本不是 void（children 是 paragraph），原判定不覆盖。
   - 文件/视频（MediaBlock）：有 useSelected 但只显示工具栏没有描边。
3. 修复方案：
   - 新建 `src/utils/whole-block-selection.ts`（唯一事实来源）：isWholeSelectableType（NON_TEXT + TABLE + HINT_BLOCK）、
     isPathCoveredBySelection（选区完整覆盖某块，允许选区更大；void 块 collapsed 也算）、useWholeBlockSelected() hook
     （useElementIf + useSlateSelector(deferred)）。withDelete / withBlockSelection / 装饰层三处共用。
   - ElementWrapper 统一打 `data-whole-selected="true"`（覆盖日历/倒计时/文件/视频/图片/时间轴/嵌入/drawio/图表/画板/提示块…）。
   - index.css 全局规则：`[data-whole-selected]` 外描边（主题色 72%）+ 内部 `::selection` 透明（压过主题选区色）。
   - Table.tsx 改用共享 hook（保留自己的 cellRangeHighlight 覆盖层，不加通用描边避免双圈）。

### 飞书表格结构分析（用户贴的 HTML）

- `docx-block-zero-space` / `data-zero-space="true"` 是**渲染层产物，不在 JSON 文档模型里**
  （证据：它们没有 data-block-id / data-record-id，真实块都有）。
- 作用等价于 Slate 的 `data-slate-zero-width`：给 contenteditable 单元格提供可锚定的选区位置
  （飞书单元格内是嵌套 editor，块边界处 DOM 没有可放光标的文本节点）。
- 结论：本项目不需要仿造 —— Slate 的 void 自带零宽 span，我们的选区处理在模型层（apply 拦截），
  不依赖 DOM 锚点。若将来做「嵌套编辑器」架构才需要考虑。
