# 2026-11-12

## FloatBar 字符格式（加粗/倾斜/下划线/行内代码）修复

用户报两个问题：① 加粗倾斜下划线设了取消不掉、选中时图标不高亮；② 每次设完格式选区有概率变成整段。

根因（两个独立 bug 叠在一起）：

1. `src/plugins/marks.ts#isMarkActive` 只读 `editor.marks` —— Slate 里它只在**折叠光标**下才是当前格式快照，
   展开选区恒为 null → 永远判定「未激活」→ `toggleMark` 永远走 addMark（取消不掉），FloatBar 也读不到激活态。
   改为：折叠时读 `editor.marks`；展开时用 `Editor.nodes` 遍历选区内非空文本节点，「全部带该 mark」才算激活。
   顺带导出 `isSelectionExpanded(editor)`，格式类操作统一用它判断有没有实际选中范围。
2. FloatBar 的工具按钮（`<button>`）没拦 mousedown → 按下时 contenteditable 失焦，Chrome 折叠/扰动 DOM 选区：
   浮栏被 `selectionchange` 关掉（点一次 B 浮栏就消失），格式可能落到整段。全部按钮补
   `onMouseDown={e => e.preventDefault()}`（ToolButton、块类型菜单项、ColorPicker 触发器/色块/重置、
   FontPicker 项、ArtTextMenu 容器）。`AlignIndentPanel` 一早就是这么写的，这次把同类组件对齐了。

改动文件：`src/plugins/marks.ts`、`src/components/FloatBar/index.tsx`、
`src/components/FloatBar/FloatBar.module.less`（新增 `.toolButtonActive`：主题色文字 + 12% 主题色底）、
`src/components/ColorPicker/index.tsx`、`src/components/FontPicker/index.tsx`、`src/plugins/art-text/ArtTextMenu.tsx`。

FloatBar 新增 `activeMarks` state：因为 core 的 `onChange` 是 no-op，只能靠 mouseup / selectionchange /
点完按钮后主动 `readActiveMarks(editor)` 回读，不依赖 Slate context 重渲染。

验证方式（headless Chrome + CDP 真实鼠标事件，脚本用完已删）：拖选 5 个字 → B/I/U 各点两次，
`editor.selection` 全程保持 `[1,0] 0→5`、`domText` 不变、图标 active 类随之开关；
混合选区（部分加粗）图标灭，点一次补齐为全加粗、再点全部取消；反向拖选、跨段拖选位置正确；
取色后选区仍在；点击按钮后 `document.activeElement` 仍在 contenteditable 内。

## 新增删除线（strikethrough）

数据层早就齐了（`CustomText.strikethrough`、`renderLeaf` 的 line-through、`withPasteConversion` 解析
`s/strike/del`、示例文档里已有删除线叶子），缺的只是入口：

- `MarkTypes.STRIKETHROUGH = 'strikethrough'`；
- FloatBar 在 U 之后加 S 按钮（图标 = 字符 S + `.iconStrike { text-decoration: line-through }`），
  激活态走上次新加的 `activeMarks` 机制（`MARK_BUTTON_KEYS` 加一项即可）；
- 快捷键 `mod+shift+x`（Tiptap / 飞书同款），`handleMarkShortcut` 的 markKey 日志表同步加一项。

CDP 实测：选中 → 点 S 加删除线且图标高亮 → 再点取消 → Ctrl+Shift+X 同样生效，选区全程不漂。
