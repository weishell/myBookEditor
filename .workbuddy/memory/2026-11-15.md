## 新增「结构守卫」withStructureGuard（Slate 丢 children / id 的根治层）

背景：排查「随便一个操作后 children / id 不见」。根因不是 bug，是 Slate 的设计：
它只有 4 条内置 normalize 规则（`slate/dist/index.es.js:2636-2754`），且默认规则会**静默销毁**
不符合判定的子节点 —— 块容器里的 text 被 `removeNodes`，行内容器里的元素被 `unwrapNodes`，
元素 children 为空时被塞 `{ text:'' }`（这一塞会让容器身份翻转成"行内容器"，之后所有块子节点被 unwrap，不可逆）。

新增文件 `src/editor-extensions/withStructureGuard.ts`：

- `withStructureGuard(editor)`：挂在**最外层**（core/index.tsx，包在 withDelete 外面），保证 normalizeNode 抢在默认规则之前。
  ① 容器块 children 为空 → 补一个「最小合法子节点」并 return（table→row→cell→paragraph 递归）；
  ② 容器块混入非元素子节点 → 包成段落保住内容（表格三兄弟除外，交给各自插件）。
  只做"补"不做"删"，幂等，不与 hint/columns/table 自己的 normalize 打架。
- `ensureUniqueIds(editor)`：split_node 会 `Node.extractProps` 整份克隆属性（含 id，见 `dist:5247` + `:696`），
  重复 id 在这里修（保留第一个，其余换新）。挂载时跑一次（`!readOnly` 才跑，只读态不动文档）。
- `inspectStructure(children)`：只读体检，返回 `{path,type,reason: empty-children|duplicate-id|missing-id}`。
- `installStructureInspector(editor)`：仅 DEV，包一层 apply，结构变脏时 `console.warn('[structure]', op.type, issues)`，
  上限 20 条防刷屏。同时把工具挂到 `window.__slateTools`（控制台可调）。
  注意：必须在 ensureUniqueIds **之后**装，否则修复过程中的中间态会误报。

验证（CDP eval，`node scripts/shot.mjs --dump --eval ...`，`window.editor`）：

- 空 hint-block → 第一个子节点是 `paragraph`（不是 inline text）✅
- hint-block 里塞纯文本 → 包成 paragraph 且文本保留 ✅
- 重复 id：检测 1 / 修复 1 / 残留 0，id 已换新 ✅
- /demo 整页渲染正常，无错误遮罩 ✅

## 生产包剥离调试日志（vite 配置层，不改源码）

需求：`console.log` 不打，`console.error` / `console.warn` 必须留着（线上定位靠它）。

做法在 `vite.config.ts`，`defineConfig` 改成函数式，按 `command` 分支：

```ts
esbuild: command === 'build'
  ? {
      pure: [
        'console.log',
        'console.debug',
        'console.info',
        'console.table',
        'console.trace',
        'console.dir',
      ],
      drop: ['debugger'],
    }
  : undefined;
```

几个必须记住的点：

- **不能用 `drop: ['console']`**：那是一刀切，`console.error` / `warn` 一起没了。
- **`pure` 单独不删代码**，只在每处调用前打 `/* @__PURE__ */` 注释（实测：不加 minify 的 transform 产物里
  只是多了注释）。真正删除发生在 minify 阶段的 tree-shaking，所以必须依赖默认的 `minify: 'esbuild'`。
- `pure` 会把整个调用**连同参数**删掉。所以只能用在 `console.log('x', {a})` 这种「参数里没有副作用调用」的地方。
  本项目扫过一遍，全是字符串 + 对象字面量读变量，安全。**以后若要写 `console.log(getSomething())`，那句话会被整段删掉。**
- 用 `command === 'build'` 而不是全局开，是为了 dev 里保留调试日志（验证过：dev 请求 `handleKeyDown.ts`
  仍有 15 处 `console.log`）。顺带 dev 也不会被塞满 `@__PURE__` 注释。

验证：

- 产物 grep：`[keydown]` / `[hint-block]` / `[lilist]` / `[Table] Caret…` 全部 0 处；`console.log` 仅剩 3 处，
  且全在 `chart-vendor`（echarts 内部把 `console.log` 当值用 / `console[r](...)` 动态调用，删不得也不该删）。
- `console.error` 39 处、`console.warn` 35 处仍在。
- 生产包上模拟 Tab/Enter/Backspace/Delete 七个按键：`console.log` 调用计数 **0**，主动 `console.error` 正常输出 1 次，
  编辑器 78 个块未受影响。
- 首页体积回归复测仍 **308 kB**（无变化）。

### split_node 克隆 id → 每次回车产生重复 id

slate 的 `Transforms.splitNodes` 走 `Node.extractProps(node)`（`dist:5247`）**整份克隆属性**，把自定义 `id` 也给了新节点；
而 `ensureUniqueIds` 只在编辑器挂载时跑一次 → 之后每次回车都多一个重复 id。

修法：`withStructureGuard` 的 `apply` 拦截点（唯一能覆盖全部拆分路径的位置：回车/粘贴/代码块分行/表格拆分）：

```ts
if (op.type === 'split_node' && op.properties && typeof op.properties.id === 'string')
  apply({ ...op, properties: { ...op.properties, id: uuidv4() } });
```

不要试图去改 `splitNodes` 各个调用点，漏一个就复发。

### 守卫规则②漏 inline 子节点

`isBlock(c) = !isInline(c)`，而 `text` 不是 element、`isInline(text)` 为 false → **`isBlock(text)` 返回 true**，
拿它当合法性判定会把裸文本放过。改成 `(c) => !Element.isElement(c) || Editor.isInline(editor, c)`。

上一轮 normalize 管的是「内容被静默改写」，这一轮管的是「内容整体没了」。

### 1. 保存失败 = 正文只活在内存里（已修）

`Article.tsx` 原来 catch 里只有 `setSaveState('error')`，而它给编辑器传的是 `persistKey=""`（关掉了 localStorage 持久化）。
所以后端 500 / 断网 / 请求挂起时，用户继续打字的内容**只存在于 React state**，切页或关标签页就没了。

新建 `src/data/draft.ts`，核心是一条不变量：

> **只要服务器没确认保存成功，localStorage 里就一定留着最新正文。**

改成「先写本机、再发请求、成功才清」，而不是「失败时再写」。理由写进注释了，简单说：
写失败草稿只能救「请求已 reject」那一刻，救不了「请求还挂着时用户继续打字」和「渲染崩了连 reject 都等不到」。

细节：

- 写入节流 1.2s（编辑器本身已有 400ms 防抖，再合并一层避免长文档反复 `JSON.stringify` 卡输入）
- 超配额（`QuotaExceededError`，正文里嵌 drawio svg data url / base64 图时会出现）只 warn，不阻断正常保存
- `flushDraft()` 用于 `pagehide` 和失败那一刻，等不到节流定时器
- `hasDraft()` 只读 key 不解析 JSON —— `beforeunload` 里要同步且快
- 删除文章时 `clearDraft()`，否则恢复时会对一篇已删除的文章弹提示

### 2. 恢复提示与「恢复即提交」

`Article.tsx` 顶部加草稿条（橙色左描边，单行，右侧两个按钮）。**「有草稿」等价于「上次没存上」**，
所以不用比时间戳猜哪份新。

`handleRestoreDraft` 里改成「灌进编辑器 + 立刻 `handleSave` 一次」：
只灌不提交的话，横幅消失了但服务器还是旧内容，下次进页面又弹一遍，用户以为已经处理完了。

### 3. `beforeunload` 拦截

只在 `hasDraft(id)` 为真时 `preventDefault`。保存成功即清草稿，所以不会误拦正常阅读。
另挂 `pagehide` → `flushDraft()`（iOS 上 beforeunload 经常不触发）。

### 4. 顶层 ErrorBoundary

新建 `src/components/ErrorBoundary/`，在 `main.tsx` 里包住 `<App />`。

- **正文快照必须在 `getDerivedStateFromError` 里抓**，不能等 `componentDidCatch`：
  那个时机 React 已经卸载了子树，`core/index.tsx` 的 cleanup 会把 `window.editor` delete 掉。
  render 阶段（旧树还在）读到才能存进 state。
- 快照有两条来源：`window.editor.children` → 回落 `/article/:id` 的 localStorage 草稿。
- chunk 加载失败单独给文案（`Failed to fetch dynamically imported module` 等）：部署新版本后老页面
  lazy import 404，这不是真崩溃，提示「页面已更新 / 刷新页面」而不是让用户以为数据没了。
- 错误详情收在 `<details>` 里，普通用户不用看。

### 验证（CDP 实跑，临时文章 + 测完 DELETE + 回收站 purge，真实数据零污染）
