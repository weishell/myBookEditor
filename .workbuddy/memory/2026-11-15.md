## 新增「结构守卫」withStructureGuard（Slate 丢 children / id 的根治层）

背景：排查「随便一个操作后 children / id 不见」。根因不是 bug，是 Slate 的设计：
它只有 4 条内置 normalize 规则（`slate/dist/index.es.js:2636-2754`），且默认规则会**静默销毁**
不符合判定的子节点 —— 块容器里的 text 被 `removeNodes`，行内容器里的元素被 `unwrapNodes`，
元素 children 为空时被塞 `{ text:'' }`（这一塞会让容器身份翻转成"行内容器"，之后所有块子节点被 unwrap，不可逆）。

新增文件 `src/editor-extensions/withStructureGuard.ts`：

- `withStructureGuard(editor)`：挂在**最外层**（core/index.tsx，包在 withDelete 外面），保证 normalizeNode 抢在默认规则之前。
  ① 容器块 children 为空 → 补一个「最小合法子节点」并 return（table→row→cell→paragraph 递归）；
  ② 容器块混入非元素子节点 → 包成段落保住内容（表格三兄弟除外，交给各自插件）。
  只做"补"不做"删"，幂等，不与 hint/columns/table 自己的 normalize 打架。
- `ensureUniqueIds(editor)`：split_node 会 `Node.extractProps` 整份克隆属性（含 id，见 `dist:5247` + `:696`），
  重复 id 在这里修（保留第一个，其余换新）。挂载时跑一次（`!readOnly` 才跑，只读态不动文档）。
- `inspectStructure(children)`：只读体检，返回 `{path,type,reason: empty-children|duplicate-id|missing-id}`。
- `installStructureInspector(editor)`：仅 DEV，包一层 apply，结构变脏时 `console.warn('[structure]', op.type, issues)`，
  上限 20 条防刷屏。同时把工具挂到 `window.__slateTools`（控制台可调）。
  注意：必须在 ensureUniqueIds **之后**装，否则修复过程中的中间态会误报。

验证（CDP eval，`node scripts/shot.mjs --dump --eval ...`，`window.editor`）：

- 空 hint-block → 第一个子节点是 `paragraph`（不是 inline text）✅
- hint-block 里塞纯文本 → 包成 paragraph 且文本保留 ✅
- 重复 id：检测 1 / 修复 1 / 残留 0，id 已换新 ✅
- /demo 整页渲染正常，无错误遮罩 ✅

### A. echarts 从「文档页必下」变成「有图表才下」

  这个文件只把 `echarts.EChartsOption` 当类型用，一行改完就断掉了静态链。

## 生产包剥离调试日志（vite 配置层，不改源码）

需求：`console.log` 不打，`console.error` / `console.warn` 必须留着（线上定位靠它）。

做法在 `vite.config.ts`，`defineConfig` 改成函数式，按 `command` 分支：

```ts
esbuild: command === 'build'
  ? {
      pure: [
        'console.log',
        'console.debug',
        'console.info',
        'console.table',
        'console.trace',
        'console.dir',
      ],
      drop: ['debugger'],
    }
  : undefined;
```

几个必须记住的点：

- **不能用 `drop: ['console']`**：那是一刀切，`console.error` / `warn` 一起没了。
- **`pure` 单独不删代码**，只在每处调用前打 `/* @__PURE__ */` 注释（实测：不加 minify 的 transform 产物里
  只是多了注释）。真正删除发生在 minify 阶段的 tree-shaking，所以必须依赖默认的 `minify: 'esbuild'`。
- `pure` 会把整个调用**连同参数**删掉。所以只能用在 `console.log('x', {a})` 这种「参数里没有副作用调用」的地方。
  本项目扫过一遍，全是字符串 + 对象字面量读变量，安全。**以后若要写 `console.log(getSomething())`，那句话会被整段删掉。**
- 用 `command === 'build'` 而不是全局开，是为了 dev 里保留调试日志（验证过：dev 请求 `handleKeyDown.ts`
  仍有 15 处 `console.log`）。顺带 dev 也不会被塞满 `@__PURE__` 注释。

验证：

- 产物 grep：`[keydown]` / `[hint-block]` / `[lilist]` / `[Table] Caret…` 全部 0 处；`console.log` 仅剩 3 处，
  且全在 `chart-vendor`（echarts 内部把 `console.log` 当值用 / `console[r](...)` 动态调用，删不得也不该删）。
- `console.error` 39 处、`console.warn` 35 处仍在。
- 生产包上模拟 Tab/Enter/Backspace/Delete 七个按键：`console.log` 调用计数 **0**，主动 `console.error` 正常输出 1 次，
  编辑器 78 个块未受影响。
- 首页体积回归复测仍 **308 kB**（无变化）。

## 复制粘贴的 id 治理（已完成）

结论：**节点 id 早就有**（`withEditorBehaviors.regenerateIds`，三条粘贴路径全覆盖，含内部 fragment →
slate 原生 `insertFragmentData` → `e.insertFragment(parsed)` 回到被劫持的版本），**插件 attrs 内的 id 之前没有**。

本次补的三件：

1. `regenerateAttrsIds`（`withEditorBehaviors.ts`）：粘贴时给 timeline `attrs.items[].id`、
   calendar `attrs.events[].id` 换新。图片/视频/附件的 `attrs.url` **不换**（共享同一媒体文件是正确的）。
2. 画板丢数据的真 bug：`attrs.src` 指向 `data/media/drawboards/*.json`，服务端 `saveDrawboard` 的语义是
   「有 path 就覆盖」→ 粘贴出的副本和原件共用同一文件，编辑副本会覆盖原图数据。
   修法：`server/services/drawboard.service.js#saveDrawboard` 增加 `copyFrom` 分支（复制到新文件名）；
   前端 `src/data/media.ts#copyDrawboard`；`src/plugins/drawboard/pasteDrawboards.ts` 在 `insertFragment`
   之后异步复制 → 按换新过的节点 id 回定位 → `HistoryEditor.withoutSaving` 回写 attrs.src
   （撤销要整体撤掉粘贴，不留一次 src 替换）。复制失败保留原 src，绝不删块。
3. 未动（有歧义，待用户决定）：`attrs.lilist.list_id` 粘贴后仍沿用原组 → 粘贴出的列表项并入原列表编号。
   在同一列表下方粘贴时「接着编号」可能才是期望行为，所以没改。

calendar/timeline，会假阳性）：
画板 src 换成新文件 ✅ / drawboard 节点 id 换新 ✅ / calendar event id 换新 ✅ / timeline item id 换新 ✅ / 页面渲染正常 ✅
