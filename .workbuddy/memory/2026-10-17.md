## 架构分析：本地 SQL 可写 / 线上静态只读（结论写入 docs/local-sql-and-netlify-read.md）

- 需求：dev 走本地 SQL 对文档增删改查，线上 Netlify 转成 JSON 等只读格式，只求查+读。
- 结论：**本地 Express(node:sqlite) 可写 + 构建时导出 JSON 快照，线上零后端**。否决原设计文档
  「浏览器 sql.js 打开 .db」（要下 1.2MB wasm + 全量 db，只为读一篇文章不划算）。
- 关键实测/现状：
  - 本机 Node 22.22.2 直接 `require('node:sqlite')` 可用（DatabaseSync，仅 experimental 警告）→ 本地后端零依赖、真文件增量写，避免 demo 里"每次写全量 export"的坑。
  - 页面全部**同步** import `src/data/articles.ts` 常量 → 用「main.tsx 先 bootstrap 快照写进 store」保持同步 API，5 个页面零改动；详情页正文按需 fetch 需 1 个 hook。
  - 线上数据分层：`/data/meta.json` + `/data/articles.json`（不含正文）+ `/data/content/<id>.json`。
  - Netlify 当前**没有 netlify.toml / \_redirects** → 深层链接 404，这是"部署后不能阅读"的头号原因；需 `/* → /index.html 200` + `/data/*` 短缓存。
  - 必须 `data/`（app.db + 正文 json）进 git，否则 Netlify 构建时无源可导；`public/data` 是产物要 gitignore。
- ⚠️ 发现既有 bug：`Article.tsx` 传给 BookEditor 的 persistKey 缺失 → 默认共用 `mybook-editor-content-v1`，
  编辑 A 后再开 B 会显示 A 的内容；编辑过 /demo 后所有文章都变成示例文档。接库前必须先修（按 `article:<id>` 分 key）。
- 交接：方案文档第 9 节留了 3 个待拍板项（db 进 git vs JSON 为真相 / 详情页按需 vs 内联正文 / 线上是否要写）。

## 落地：本地 SQLite 索引 + 线上静态 JSON（按用户三条决定）

- 用户拍板：① 库只存索引（标题/json 地址/id/时间/类型/标签），不存正文；② 前端自己判断环境，越简单越好，
  本地要像真数据库；③ 正文/图片/其他文件/画板分目录，只存相对地址。
- 实现：
  - `data/`：`meta.json`（分类标签）+ `articles/<id>.json`（一篇一文件，含正文）+ `drawboards/` + `media/{images,files,videos}`；
    `index.db` 是 `node:sqlite` 索引，启动时从文件全量重建（文件=真相）。
  - `server/`：零依赖 `node:http` + `node:sqlite`。`config/articles/db/router/index` 五个模块；
    REST：health/meta/articles CRUD + `PATCH :id/autosave` + `/api/rebuild` + `/api/upload`（原始字节流）+ `/media` 静态托管。
  - 前端：新增 `src/data/{types,store,demo-data,bootstrap}.ts`，`articles.ts` 改为同步选择器；
    `main.tsx` 先 bootstrap 再 render；详情页正文按篇懒加载（缓存按 `{id, content}` 成对，避免闪上一篇）。
  - 编辑器：`BookEditor` 加 `onSave`（400ms 防抖 + 卸载补交），文章页 `persistKey=""` 走服务端。
  - 首页：可写模式显示「＋新建文档」（`NewArticleModal`）与「最近更新」；文章页有保存状态与删除（确认框）。
  - 部署：`scripts/export-static-data.mjs` → `public/data`；`netlify.toml`（SPA 回退 + /data 短缓存 + NODE_VERSION 22）；
    `package.json` build 串上导出；`.gitignore` 加 `public/data`、`public/media`、`data/index.db*`、`data/.trash`。
- 坑：
  - `unlink` 被本机 safe-delete shim 拦截（`trash operation aborted`）→ 删除改 `rename` 进 `data/.trash/`。
  - `fs.rmSync` 清 `public/data` 也会告警失败 → 导出脚本 catch 掉继续写（覆盖同名文件即可）。
  - `agent-browser` 在本机不可用（node loader 报错），浏览器验证只能靠用户自己看页面。
- 验证：`tsc -b` EXIT=0；`vite build` 成功且 `dist/data/*` 齐全；`vite preview` 下 `/data/*`、`/article/<id>`、`/demo` 均 200；
  经 5173 代理跑通 创建→autosave→读取→删除（列表 6→7→6）。
