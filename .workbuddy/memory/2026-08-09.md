## 表格行列头点击无效 - 彻底修复

### Root Cause（真正的根因）

`handleSelectRow/Col` 只设置了 React state，但没有同步更新 Slate 选区。当 `setSelectedCol(1)` 执行后，useEffect 立即重新执行（因为依赖中有 `selectedCol`）。此时 `editor.selection` 仍停留在第一列（因为 `mousedown` 被阻止了），useEffect 发现 `selectedCol(1) !== colIdx(0)`，立即清除了选中态。**只有点击的列刚好等于当前 Slate 选区所在列时（默认光标在第一列，所以只有第一列能"工作"），选中态才能保留。**

### 修复内容

- `src/plugins/table/Table.tsx`:
  - `handleSelectRow` / `handleSelectCol` 中同步调用 `Transforms.select`，将 Slate 选区设置到对应行/列的第一个单元格，确保 useEffect 检查时匹配
  - 新增 `skipAutoClearRef`，在手动选中的瞬间跳过 useEffect 的自动清除逻辑，双重保险
  - 行头 `left: 0`、列头 `top: 0`，改回表格内部边缘，避免被父容器 `overflow:hidden` 截断
- `src/plugins/table/Table.module.less`:
  - 行头：`left: 0; width: 14px`，淡灰背景（rgba 3%）+ 左侧 3px 竖线，hover/选中变主题色
  - 列头：`top: 0; height: 14px`，同理淡灰背景 + 顶部 3px 横线
  - 点击区域 14px，不会被截断，视觉上只有 3px 细线
  - 暗黑模式：淡灰背景改用白色 rgba，竖线/横线颜色适配

## 表格列头重叠 + 按钮位置修复

### Root Cause

1. `colDots` 计算使用相邻单元格中点，当单元格 `getBoundingClientRect()` 返回异常值时，导致 `colDots` 值不递增，列头宽度为 0 或重叠。截图中红色区域是一个连续长条覆盖了整个顶部，说明第二、三、四列列头重叠了。
2. `useEffect` 自动清除逻辑依赖 `selectedCol` 状态，容易形成循环清除。即使加了 `skipAutoClearRef`，在 React 18 自动批处理下仍可能时序错乱。
3. 删除工具栏 `top: -32px` 太远离表格，用户注意不到。

### 修复内容

- `src/plugins/table/Table.tsx`:
  - `colDots` 计算改为直接取单元格左边界（不再用中点），并强制 `Math.max(left, prevLeft)` 确保严格递增
  - 列头渲染添加等宽分布 fallback：当 `colDots` 测量异常导致宽度 < 10px 时，强制使用 `tableSize.width / colCount` 等宽分布
  - 移除 `useEffect` 自动清除逻辑，改为用 `selectedRowRef` / `selectedColRef` 跟踪状态，避免循环依赖
- `src/plugins/table/Table.module.less`:
  - 删除工具栏 `top: -32px` → `top: -4px`，紧贴表格上方
  - 列头添加 `border-right: 1px solid @border-color`，让每列独立可见

## 表格列头混用测量值和 fallback 导致重叠

### 修复内容

- `src/plugins/table/Table.tsx`:
  - 列头渲染前先统一检查：如果任何一列的测量宽度 < 10px，**全部**使用等宽分布 fallback，不再混用
  - `useLayoutEffect` 中 `cells.length !== colCount` 时也触发重试，确保测量基于正确的单元格数量

## 表格列头彻底重写 - colBounds 方案

### Root Cause

之前所有方案都在 `colDots`（边界点数组）上做文章，但 `colDots` 的计算太脆弱：依赖 `getBoundingClientRect()` 在 `border-collapse: collapse` 表格上的返回值，容易受边框合并、滚动、亚像素渲染影响，导致相邻列的边界值相同，列头宽度为 0 或重叠。

### 修复内容

- `src/plugins/table/Table.tsx`:
  - 新增 `colBounds` state：`Array<{left, width}>`，直接存储每列的左边界和宽度，不再通过边界点差值计算
  - `useLayoutEffect` 中直接遍历每列单元格，`rect.left - wrapperRect.left` 得左边界，`rect.width` 得宽度
  - 列头渲染使用 `colBounds[i].left` 和 `colBounds[i].width`，每列独立，不会重叠
  - 如果 `colBounds.length !== colCount` 或任何列宽度 < 10px，统一使用等宽分布 fallback
  - `colDots` 仍然保留，仅用于插入列圆点和拖拽手柄

### 修复内容

- `src/plugins/table/Table.tsx`:
  - **重写删除逻辑**：`handleDeleteSelectedRow/Col` 直接使用 `Transforms.removeNodes` 删除指定行/列，不再调用 `deleteRow`/`deleteColumn`
  - 删除列时从最后一行开始删（`for rowIdx = rows.length-1; rowIdx >= 0; rowIdx--`），避免路径变化
  - 如果只剩一行/一列，删除整个表格
  - **按钮位置**：选中列时按钮出现在该列上方居中（`left: colBounds[i].left + width/2`），选中行时出现在该行左侧上方（`top: rowDots[i].top - 36`）
  - **列头计算**：使用 `getBoundingClientRect()` 但添加 `Math.max(left, prevRight)` 防御性检查，确保列头不重叠且随滚动同步
  - 清理未使用的 `deleteRow`/`deleteColumn` 导入
- `src/plugins/table/Table.module.less`:

## 表格列头高亮覆盖整个表格修复

### 修复内容

- `src/plugins/table/Table.tsx`:

  - `selectedColHighlight`、`hoverColHighlight`、`dragColHighlight` 全部改用 `colBounds[i]` 而不是 `colDots` 差值，确保只覆盖选中的列
  - `colBounds` 计算保留 `Math.max(left, prevRight)` 防御性检查，确保列头不重叠

## 表格列头大通铺 + 删除列总删第一列 — 最终修复

### Root Cause（真正的根因）

`colBounds` 是独立于 `colDots` 的 state，尽管 `colDots` 的值已被证实正确（圆点能正确显示在每列边界），但 `colBounds` 的计算方式不同（用 `Math.max` 防御性检查 + `prevRight` 跟踪），可能在某些边界条件下产生错误值。而列头渲染依赖 `colBounds`，圆点渲染依赖 `colDots`，导致"圆点正确但列头错误"的矛盾。

### 修复方案（统一用 colDots）

彻底放弃 `colBounds`，列头渲染与圆点使用**完全相同的数据源** `colDots`：

- 列头 i：`left = colDots[i].left`, `width = colDots[i+1].left - colDots[i].left`（与行头用 `rowDots` 完全对称）
- `selectedColHighlight`、`hoverColHighlight`、`dragColHighlight`、工具栏位置 全部改用 `colDots[i]` 和 `colDots[i+1]` 差值
- 移除 `colBounds` state 和相关计算

### 为什么这次能修复

- 圆点（colDots）已被用户截图证实每列边界位置正确
- 行头（rowDots）已被证实能正确选中每行
- 列头现在与圆点用同一份 colDots 数据，与行头用同一套定位模式（dots[i] ~ dots[i+1]）
- 删除列 `handleDeleteSelectedCol` 逻辑本身正确（直接用 selectedCol 路径删除），之前失效是因为列头重叠导致 selectedCol 总是 0

## 表格列头点击 — 单 overlay 方案（最终最终修复）

### Root Cause

统一用 `colDots` 后列头位置正确，但用户截图显示仍然只有第一列能选中。说明问题不是定位，而是**事件分发**——多个绝对定位 div 存在未知的 z-index/重叠/事件拦截问题，导致只有第一列的 onClick 能被触发。

### 修复方案（单 overlay）

彻底放弃"每个列一个 div + 各自绑定 onClick"，改为**一个透明 overlay 覆盖整个表格顶部**：

- `div.colHeaderOverlay` 覆盖 `top:0` 到 `height:14px`、`width:tableSize.width` 的区域
- `z-index: 16`，确保在所有元素（包括拖拽手柄 z-index:15）之上
- `onClick`：通过 `e.clientX - rect.left` 计算鼠标 x 坐标，遍历 `colDots` 边界判断点击了哪一列
- `onMouseMove`：同样计算坐标，设置 `hoveredCol` 状态
- 列头视觉条（`.colHeader`）仅用于显示，设置 `pointerEvents: 'none'`，事件全部透传给 overlay
- 新增 `.colHeaderHovered` 类，通过 `hoveredCol === i` 动态添加，替代 CSS `:hover`（因为 pointerEvents:none 元素收不到 hover）

### 改动文件

- `src/plugins/table/Table.tsx`：添加 `colHeaderOverlay`，列头 div 移除所有事件处理器，仅保留视觉
- `src/plugins/table/Table.module.less`：添加 `.colHeaderOverlay`、`.colHeaderHovered`，暗黑模式适配
