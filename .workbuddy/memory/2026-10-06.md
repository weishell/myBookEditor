## Shift+Enter 软换行（块内 `\n`）— 新增

用户需求：「Shift+Enter 相当于 `\n`，而不是一个新的插件（新块）」。

**根因（读 slate 源码确证）**：浏览器对 Shift+Enter 触发 `beforeinput(insertLineBreak)`，
slate-react 转成 `Editor.insertSoftBreak`；而本项目 slate 0.126.2 里它的实现是
**`Transforms.splitNodes(editor, { always: true })`** —— 直接拆块，根本不写 `\n`。
所以「Shift+Enter = 回车」这个假象，就是它就是拆块导致的。

**实现**：

- `src/events/keyboard/handleKeyDown.ts`：Enter 分支里 `e.shiftKey` 时改为
  `Transforms.insertText(editor, '\n')`（与代码块 `handleEnter` 里现成写法一致）；
  `isKeyConsumed` 里 Enter 一律返回 `true`；`Element` 从 slate 导入时起别名 `SlateElement`。
  稳健性：命中 void 块时返回 false 不写（void 子文本不参与渲染）。
- `src/index.css`：新增 `[data-slate-editor] [data-slate-string] { white-space: pre-wrap; }`。
  slate-react 把文本渲染进 `<span data-slate-string>`，默认 `white-space: normal`
  会把 `\n` 折叠成空格 → 看起来「没反应」。pre-wrap 后才真正折行。

**验证（真实 slate 探针）**：旧路径 `Editor.insertSoftBreak` → **2 个块**（bug 复现）；
新路径 `insertText('\n')` → **1 个块**，文本 `"hello\n world"`。`tsc -b` 0 报错。

## 已有约定（本轮查证，供复用）

- 代码块靠 `Transforms.insertText(editor, '\n')` + `CodeLine.module.less` 的 `pre-wrap` 实现换行——
  段落软换行就是把这套推广到所有块。
- 键盘事件唯一入口 `src/events/keyboard/handleKeyDown.ts`（core/index.tsx 的 `onKeyDown`），
  各键 handler 在 `src/events/keyboard/` 下。

## 列表项悬挂缩进（换行文字不再压到序号下面）

用户需求：有序列表换行后，文字不应跑到序号（`2.`）下面，应左对齐首行文字。

**现状成因**：`LilistPrefix` 渲染成一个 `inline-block` 的序号 span（`text-align:right` + 槽位宽度），
它是 `<p>`/`<h*>` 里的**行内首元素**；文字换行后回到块的**内容盒左缘**，于是压在序号下面。

**实现（悬挂缩进）**：给块加 `padding-left: <槽位>` + `text-indent: -<槽位>`，
首行被负缩进拉回左边（放序号），后续行停在 padding 处（与首行文字左对齐）。
槽位宽度 = 序号占位宽(`getLilistPrefixWidth`) + `6px`(前缀 margin-right)，**两处必须同源**，
否则对不齐。序号本身仍用 `min-width`（不是 width）：位数超出时方框变宽，
宁可首行文字右移几像素，也不让编号溢出压到正文。

- `lilist-model.ts`：新增 `getLilistPrefixWidth(element)` → UL `1.2em` / OL `1.6em` / 标题有序 `2.6em`（层级路径更长）。
- `LilistPrefix.tsx`：前缀内联 `minWidth = getLilistPrefixWidth(element)`。
- `Paragraph.tsx` / `Heading.tsx`：有 lilist 时给 `<p>`/`<h1>` 内联
  `paddingLeft: calc(W + 6px)`、`textIndent: calc(-1 * (W + 6px))`。

**验证**：用本机真实 Chrome 无头渲染了 5 组对比（现象复现 + 单/双位数 + 无序 + 标题），
对比图存 `.workbuddy/artifacts/lilist-hang-compare.png`。`tsc -b` 0 报错。

**已知边界**：块设为「居中对齐」的列表项，首行会被 `text-indent` 额外左移（列表极少居中，未处理）。
